# Channel Adapter Layer

كل القنوات بتتكلم مع SIE من خلال طبقة واحدة. SIE نفسه مايعرفش إن تيليجرام
موجود أصلاً.

```
   Website ─┐
  Telegram ─┤
  WhatsApp ─┼─> handleInbound() ─> SieClient ─> sie-runtime.js ─> SIE
 Messenger ─┤
       API ─┘
```

إضافة قناة جديدة = مجلد جديد + `register()`. مفيش أي تغيير في المحرك ولا في
الطبقة ولا في أي محوّل تاني.

---

## القاعدة اللي بتحافظ على الطبقة

| المجلد | مسموح يعرف إيه |
|---|---|
| `core/` | لا شيء عن أي بائع — الصيغة القياسية، المسار، الجلسات، الهوية، الإعادة، التسجيل |
| `telegram/` | كل تفاصيل تيليجرام، ومفيش حاجة منها بره المجلد ده |
| `whatsapp/` `messenger/` `website/` `api/` | تفاصيل القناة بتاعتها بس |

`channels/tests/channel-layer.test.mjs` بيقرا الكود المصدري ويفشل لو حد كسر
القاعدتين دول، فمش مجرد كلام في README.

---

## الواجهة

كل محوّل بينفّذ أربع دوال:

```js
{
  name,                                  // من CHANNELS
  verify(request) -> {ok, reason?},      // الطلب ده من القناة فعلاً؟
  parse(payload)  -> InboundMessage[],   // صيغة القناة -> الصيغة القياسية
  send(chatId, OutboundMessage),         // الصيغة القياسية -> صيغة القناة
  typing?(chatId)                        // اختياري
}
```

`parse` بترجّع **مصفوفة** لأن واتساب وماسنجر بيجمّعوا كذا رسالة في طلب واحد.
تيليجرام بيبعت واحدة، فبترجّع مصفوفة من عنصر واحد — وده بيخلّي المسار المشترك
له طريق واحد مش اتنين.

**ممنوع** على أي محوّل يكلّم SIE أو `chat_sessions` أو دوال الرصيد مباشرة. ده
كله بيحصل مرة واحدة في `handleInbound()`.

---

## ترتيب المسار (مش عشوائي)

1. **verify** — الطلب غير الموثّق بيتفلتر قبل ما يكلّفنا أي حاجة.
2. **parse** — صيغة البائع بتموت هنا.
3. **dedupe** — قبل الرصيد، عشان إعادة الإرسال ماتخصمش رسالة تانية.
4. **identity** — مين ده بلغة مدعوم؟
5. **SIE** — النقطة الوحيدة.
6. **send** — بإعادة محاولة، لأن الرد اتحسب وخصم رصيد بالفعل.

---

## الهوية: ليه لازم ربط

`sie_consume_message` بيخصم من رصيد حساب معيّن، وكل كتابة في المسار مربوطة
بـ `chat_sessions` بيملكها `auth.users.id` حقيقي. اللي بيكتب على تيليجرام
مالوش أي حاجة من دول — هو رقم في فضاء تيليجرام وبس.

**الاختصار الخطر:** إنك ترد على أي حد ييجي وتحسبه على حساب افتراضي. ده معناه
إن أي غريب يلاقي البوت يقدر يصرف رصيد عميل بيدفع، ويفتح تذاكر باسمه.

عشان كده:

1. العميل بيطلب كود من صفحة الإعدادات (`channel_create_link_code`)
2. بيبعت الكود للبوت (أو `/start ABCD2345`)
3. `channel_redeem_link_code` بيربط `chat_id` بالحساب — مرة واحدة، والكود ينتهي بعد ١٥ دقيقة

المحادثة غير المربوطة بتاخد شرح، **مش** إجابة.

### ليه جدول جديد مش `profiles.telegram_chat_id`

العمود ده موجود بس معناه حاجة تانية خالص: هو المكان اللي المنصة بتبعت عليه
أكواد التحقق بخطوتين وتنبيهات التذاكر **لصاحب الحساب**، وبيكتبه دالة
`telegram-webhook` الموجودة. لو استخدمناه، العميل اللي يربط محادثة دعم هيحوّل
أكواد الأمان بتاعته لنفس المكان من غير ما يدري.

---

## الأمان

| التهديد | الدفاع |
|---|---|
| طلب مزوّر على الويبهوك | `secret_token` بتاع تيليجرام، مقارنة بوقت ثابت |
| تسريب السر بقياس الوقت | `constantTimeEquals` — مقارنة كل الحروف مهما حصل |
| نشر من غير سر | فشل مقفول: سر فاضي = رفض كل تحديث، مش سماح |
| صرف رصيد حد تاني | الربط إجباري؛ الحساب بيتحدد من `channel_identities` |
| تخمين أكواد الربط | ٨ حروف من أبجدية ٣١، مرة واحدة، ١٥ دقيقة، والدالة `service_role` بس |
| رد مكرر يخصم مرتين | `deduplicationKey` قبل أي صرف |
| تسريب أسرار في اللوج | `redact()` على كل payload، والتوكن مابيتسجلش أبدًا |

الأسرار كلها من البيئة. `channel-layer.test.mjs` بيفحص المصدر ويفشل لو لقى
شكل توكن بوت أو JWT مكتوب في الكود.

## التشغيل محليًا

مفيش build step. الملفات ESM عادية وبتشتغل في Node وDeno.

```bash
# الاختبارات — من غير شبكة ولا توكن ولا نشر
node --test "channels/tests/*.test.mjs"

# كل حاجة
node --test "sie/**/tests/*.test.mjs" "channels/tests/*.test.mjs"
```

لتجربة الويبهوك على جهازك:

```bash
export TELEGRAM_BOT_TOKEN='...'          # من @BotFather
export TELEGRAM_WEBHOOK_SECRET='...'     # أو سيبه فاضي والسكربت هيولّده

supabase functions serve sie-channel-telegram --no-verify-jwt

# تيليجرام محتاج HTTPS، فلازم نفق
ngrok http 54321
node scripts/telegram-webhook.mjs set --url https://<ngrok>.ngrok.io/functions/v1/sie-channel-telegram
```

## النشر للإنتاج

```bash
# 1) الأسرار — مش في الكود ولا في git
supabase secrets set TELEGRAM_BOT_TOKEN='...'
supabase secrets set TELEGRAM_WEBHOOK_SECRET='...'

# 2) الدالة. لاحظ --no-verify-jwt: تيليجرام مش هيبعت JWT بتاع Supabase،

# 3) تسجيل الويبهوك
node scripts/telegram-webhook.mjs set \
  --url https://srnelrdpqkcntbgudyto.supabase.co/functions/v1/sie-channel-telegram

# 4) التأكد
node scripts/telegram-webhook.mjs info
```

`info` بيعرض آخر خطأ شافه تيليجرام — أهم سطر لما الويبهوك يسكت من غير سبب واضح.

### ⚠️ الدالة الموجودة `telegram-webhook` متتلمسش

فيه دالة `telegram-webhook` شغّالة بالفعل، وهي **مش** قناة محادثة: بتخدم بوتات
التنبيهات لكل عميل (`customer_telegram_bots`) وبتبعت إشعارات التذاكر. الـ URL
بتاعها مسجّل عند كل عميل. القناة دي على slug منفصل تمامًا عشان الاتنين يشتغلوا
مع بعض.

## SIE وStreaming

المحرك مابيعملش streaming. `getSieReply()` بترجّع رد كامل في `await` واحد، لأن
آخر مرحلة في المسار بتكتب الرسالة والتذكرة في transaction واحدة — مفيش حالة
جزئية أصلاً تتبعت.

فالطبقة request/response عادي، وده كمان اللي تيليجرام عايزه: Bot API مالوش
إرسال متدفّق، و`editMessageText` كل شوية تجربة أسوأ من رد كامل مرة واحدة. لو
المحرك اتطوّر وبقى بيتدفّق، ده هيحصل ورا نفس `reply()` من غير ما أي محوّل
يتغيّر.

## حدود معروفة

- **إزالة التكرار في الذاكرة بس.** بتمسك الحالة اللي بتحصل فعلًا (تيليجرام
  بيعيد الإرسال بعد ثواني لأن الرد اتأخر) على نفس نسخة الدالة. ضمان عبر النسخ
  محتاج تخزين مشترك.
- **الصور والصوت بيتقروا بس ومابيتفهموش.** `attachments` موجودة في الصيغة
  القياسية من دلوقتي، والمحرك لسه نصّي — فالصورة من غير تعليق بتاخد رد صريح
  بدل ما تدخل المسار وترجع رد مالوش معنى.
- **واتساب وماسنجر شكلهم جاهز والتوصيل لأ.** مدعوم عندها `whatsapp-webhook`
  و`meta-webhook` شغّالين في ريبو المنصة. نقلهم على الواجهة دي تغيير في ريبو
  المنصة، وماتعملش من هنا عشان مانحوّلش ترافيك حقيقي على كود ماتجربش.
- **الموقع لسه مانتقلش.** ودجت مدعوم بينادي `sie-runtime.js` مباشرة. المحوّل
  موجود عشان يبقى فيه طريق، والنقل تغيير في ريبو المنصة.
- **نشر Deno ماتجربش من هنا.** كل المنطق متجرّب في Node، لكن الـ Edge Function
  نفسها محتاجة smoke test بعد أول نشر — تحديدًا إن `/sie/**/*.json` بتتحمّل
  جوه بيئة Deno.
